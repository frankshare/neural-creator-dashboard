## 一、这条线在做什么

把用户在 X（推特）收藏的帖子，逐条做**深度解读**归档进 Obsidian 库，再把归档内容**挂载**到一个类似 `luoluo-121/neural-creator-dashboard` 的个人工作台界面上（**用自己的内容，不用上游的示例库**）。

| 环节 | 输入 | 输出 | 落盘位置 |
| --- | --- | --- | --- |
| 枚举 | X 书签页 | 20 条书签清单 | `3-资料\X书签归档进度.md` |
| 归档 | 每条帖子 | 每条 1 个目录 × 3 个文件 | `3-资料\X书签归档\<类型>｜<主题>\` |
| 索引 | 全部归档 | dataview 自动索引 | `3-资料\X书签归档索引.md` |
| 导入 | 归档笔记 | 面板数据 `my-data.js` | `E:\dev\neural-creator-dashboard\src\data\` |
| 部署 | 仓库 | 线上静态站 | GitHub Pages |

### 每条帖子的 3 个文件分工

| 文件 | 写什么 |
| --- | --- |
| `导读.md` | 一句话简介、核心方法论、**可读目录**、它解决了什么 / 不解决什么 |
| `帖子.md` | 原文**逐字**摘录、归纳与解读、媒体说明 |
| `链接内容.md` | 帖内链接网站的**主动总结**、内容结构解读、关键结论、**未能获取的部分** |

### 命名规范

- 目录：`<类型>｜<主题>`，类型取「文档 / 研究 / 合集 / 工具合集 / Skill合集」
- 分隔符用**全角 ｜**（U+FF5C）；**表格内**用半角 `|`（否则破坏表格语法）
- 避开 Windows 非法文件名字符

## 三、可复用的流程（命令级）

### 3.1 归档（人工 + 工具混合，逐条）

每条帖子都走同一套：抓正文 → 抓链接网站正文 → 写 3 个文件 → 缺口写进「未能获取的部分」。
**抓不到就写抓不到，不编造** —— 这是这条线唯一的硬底线。

### 3.2 导入面板

```powershell
cd E:\dev\neural-creator-dashboard
node scripts/import-notes.mjs `
  --vault "D:\Obsidian\MyVault" `
  --collects "3-资料\X书签归档" `
  --ideas "1-收集箱" --drafts "2-我的想法" --methods "3-资料\模板" `
  --all-as-notes --group-works `
  --exclude "归档索引" --exclude "归档进度" `
  --account "我的笔记"
```

- `--group-works`：把一个归档目录的 **3 个 md 聚合成 1 条**收藏（优先取 `导读.md`）。**不加会把 1 条帖子算成 3 条。**
- `--exclude`：**必须排除** `归档索引` 与 `归档进度` 两个账本文件 —— 它们含跳过条目的标题，会把**不该进面板的内容**带进来。

### 3.3 自检

```powershell
node scripts/verify.mjs
```

### 3.4 发布（示例库版本）

```powershell
node scripts/import-notes.mjs --reset          # 切成 sample 数据
node node_modules/vite/bin/vite.js build        # 构建静态站
```

> ⚠️ `--reset` 会把 `src/data/index.js` 改回指向 `sample.js`。**本地开发要再导入一次真实数据**，否则面板变回示例库。

## 四、归档纪律（沿用，勿破）

1. **抓不到就写「未能获取」，绝不编造。**
2. **推断必须标 `推断`**（含由结构反推的结论）。
3. **原文摘录逐字**，不改写；英文引文保持英文。
4. **灰区内容必须带 `> [!warning]`**，按「风险样本」而非「操作指南」定位。
5. **模型不能读图** → 走「截图 → Windows OCR」，且 OCR 结果必须标注为 OCR 并标出疑似误识别。
6. **`## 我的想法` 永远留空** —— 那是留给用户自己填的。
7. **补写不覆盖旧记录。** 后续补到新材料时，**新增**「后补材料」章节 + 在旧结论旁加**前向指针**，不要改掉当初写下的失败记录 —— 那些记录的是**当时的真实状态**。

## 五、⚠️ 上下文与并发纪律（本轮最大教训）

### 5.1 出过什么事

这一轮任务**因为并发铺得太开，单轮上下文被直接塞满**，导致会话无法继续推进，只能靠压缩/续接。

**具体是怎么塞满的**：

| 做法 | 后果 |
| --- | --- |
| 同时开多个子代理/并行任务 | 每个都往主上下文回一大段过程与结果 |
| 把整页 HTML、整个日志直接读进上下文 | 一次几十 KB 的噪声，信息密度极低 |
| 整篇读长文件而不先定位 | 读了几百行，真正需要的只有 20 行 |
| 结论只留在上下文里、不落盘 | 上下文一满，结论就跟着丢 |
| 同一轮里既归档又部署又调研 | 三条线互相打断，每条都留一半 |

### 5.2 硬纪律（照做）

1. **默认串行。一个会话同时最多 1–2 个子代理**；需要更多就**排队**，不要一次铺开。
2. **子代理只回结论。** 派活时明确写：「只返回结论与文件路径，不要粘贴中间输出。」
3. **大输出先过滤再进上下文。** 在 `run_code` 里用脚本聚合/截断/只打印关键字段，**不要把整页 HTML、整个日志、整篇文件原样打印**。
4. **长文件先定位再读。** 用 `grep` 找行号，再用 `read` 的 `offset`/`limit` 只读需要的段落。
5. **每个阶段立刻落盘。** 结论写进文件（笔记/文档），**不要只留在上下文里** —— 上下文会满，文件不会。
6. **重复的事就脚本化。** 同一件事做第二次，写成脚本，避免每次靠工具调用堆上下文。
7. **一轮只推进一个目标。** 不要在同一轮里既归档又部署又调研。
8. **需要汇总时用「一次调用、服务端过滤」**，而不是「多次调用、把原始结果都搬回来」。

### 5.3 正例 / 反例

```ts
// ✗ 反例：把整页 HTML 搬进上下文
const r = await tools.web_fetch({ url });
console.log(r.body.content);              // 100 KB 噪声

// ✓ 正例：在程序里过滤，只打印要的字段
const r = await tools.web_fetch({ url });
const text = strip(r.body.content);
const i = text.indexOf("Muse Video");
console.log(text.slice(i, i + 800));      // 800 字符，信息密度高
```

```ts
// ✗ 反例：并发开 5 个子代理，各自回一大段
// ✓ 正例：串行，且要求只回结论
const a = await tools.subagent({ description: "查 X", prompt: "……只返回结论与来源链接，不要过程。" });
```

## 六、这一轮踩过的坑（都已修）

| # | 坑 | 现象 | 修法 |
| --- | --- | --- | --- |
| 1 | **多帧 zstd 会话日志** | 整段解压只拿到第一帧（230 B），内容「看不见」 | 按魔数 `28b52ffd` 切帧，逐帧解压 |
| 2 | **账本文件泄进面板** | `归档索引`/`归档进度` 被当笔记导入，跳过条目标题进了面板 | 导入加 `--exclude` 两个文件 |
| 3 | **CNAME 误判** | 曾断言「Pages 已绑定自定义域名，随时会接管」 | 打开 Pages 设置看 DOM：**字段为空、状态 disabled**，从未绑定。已删除 `public/CNAME` 与 `dist/CNAME` |
| 4 | **`web_search` 401** | 一直报 `api key ****7022 is invalid` | 直连官方 API 多端点验证，确认是 **key 本身失效**（不是模型选择问题）；用户换 key 后恢复 |
| 5 | **`verify.mjs` 误报** | 「posts 为空」「模块应为 5 个」 | 0 作品是合法配置、模块已增到 6，断言已放宽 |
| 6 | **导入截断警告算错** | 把「原始笔记数」和「作品上限」比，误报「只取了最新 30 篇」 | 改成聚合后再判断 |
